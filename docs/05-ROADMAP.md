# 開発ロードマップ

## 順序とマイルストーン
0 → 1 → 2 → 3 → 4 → 5 → 6を基本とする。保護・アクセシビリティ・測定・テストは各フェーズから実施し、Phase 6へ先送りしない。
Phase 3・4の独立項目はPhase 2後に順序調整可能。Phase 5は権限・共有保存の検証完了後。
M0: 設計レビュー → M1: 実機で入力 → M2: 日本語MVP → M3: 修正・カスタマイズ → M4: 手動履歴 → M5: リリース判定。
工数は開発環境とプロトタイプの結果が出るまで数値化しない。

## Phase 0: 技術調査・設計（P0）
- 目的: 仕様・OSS・権限の前提を整理し、実装の判断材料を用意する。
- 実装対象: なし。基本設計と検証計画のみ。
- 依存: Apple公式資料、公開リポジトリ、既存のAI開発基盤。
- 主なタスク: 要件分割、OSS・ライセンス比較、保存・編集境界、対応OS候補、リスクの整理。
- 成果物: 本docs 6文書、README、選定判断。
- 完了条件: 文書が相互参照でき、確定／推奨／未確認が区別される。採用版固定と実機ゲートが計画されている。
- リスク: 可変mainの説明とmanifestの差。調査完了を実機確認済みと混同しない。
- 現状: 文書調査完了。技術選定の最終確定はPhase 1〜2の検証後。

## Phase 1: 最小動作環境（P0）
- 目的: 本体と拡張のインストール・起動・入力が成立することを確認する。
- 実装対象: Xcodeプロジェクト、本体、Custom Keyboard Extension、基本入力・削除・地球キー。
- 依存: macOS + 対応Xcode、iPhone、Apple署名環境、OS・bundle ID・App Group IDの決定。
- 主なタスク: ターゲットとentitlement作成、実機導入、本体の有効化案内、textDocumentProxyの最小アダプター、権限なし／ありの共有読取・書込試験。
- 成果物: 実機で使える最小キーボード、ホスト試験用アプリ、確認表。
- 完了条件: 再起動後も有効化でき、文字入力・削除・切替が動く。フルアクセスなしでも基本入力できる。
- リスク: 署名、App Group、拡張ライフサイクル、ホストによるキーボード拒否。

## Phase 2: 日本語入力（P0）
- 目的: 日本語入力MVPを安定させる。
- 実装対象: フリック、濁点等、入力状態、通常変換、候補・確定、英数字・記号、かな種変換、基本カーソル移動。
- 依存: Phase 1、固定した変換器版・辞書・依存のライセンス確認。
- 主なタスク: ConversionAdapter導入、marked textと確定時挿入のホスト比較、入力revision管理、辞書同梱、権限なし動作、遅延・メモリ基準測定。
- 成果物: 日本語MVP、入力状態単体テスト、変換評価用の非個人情報コーパス、採用版と性能目標の記録。
- 完了条件: 機内モードの初回起動から変換でき、候補選択と取消で文章が壊れない。連続入力で古い候補を適用しない。複数ホストで検証済み。
- リスク: 辞書サイズ、変換器の副作用、Swift依存互換、marked text、変換品質。満たさない場合は全体forkを再比較する。

## Phase 3: 操作性改善（P1）
- 目的: 入力途中・確定直後の修正の負担を減らす。
- 実装対象: ドラッグカーソル、連続／単語削除、変換修正、限定した再変換、ユーザー辞書、候補学習。
- 依存: Phase 2の入力状態・安全な編集境界、辞書形式、拡張内学習保存の検証。
- 主なタスク: 文脈・文書照合、語境界試験、Unicode試験、辞書スナップショット更新、学習ON/OFFとリセット。
- 成果物: 編集操作の仕様とテスト、辞書管理画面、学習データの削除手段。
- 完了条件: ホストやカーソルが変わった際の再変換を安全に拒否し、長押し停止が確実。辞書反映・再起動後の学習を確認。
- リスク: 部分文脈、選択テキスト、誤削除、日本語の語境界、学習による個人情報保存。

## Phase 4: レイアウト調整（P1、テーマはP2）
- 目的: 片手・縦横画面に合わせた入力面を提供する。
- 実装対象: 高さ、キー寸法・間隔、左右配置、縦横別設定。追加要件としてテーマギャラリー・カスタマイズ・プレビューを実装。詳細は [UI/UX設計](10-UI-UX-AND-THEMES.md)。
- 依存: Phase 2のUI、共有設定の読取試験。
- 主なタスク: 実際のview boundsに基づく配置、設定の制約・既定値、本体の調整画面、回転・文字拡大・VoiceOver確認。
- 成果物: 保存可能なレイアウト設定、表示・操作の検証表。
- 完了条件: 縦横変更と再起動後に設定が復元され、キーが画面外へ出ず、最小操作領域を維持する。
- リスク: ホストが許す高さ、safe area、画面サイズ、極端な設定による操作不能。

## Phase 5: クリップボード（P2）
- 目的: 明示的に保存したテキストを繰り返し利用する。
- 実装対象: 手動取込・プレビュー、SQLite履歴、一覧、1件挿入、削除、重複排除、ピン、ローカル検索。
- 依存: Phase 1の権限試験、Phase 2の挿入処理、SQLite並行アクセス・保護・マイグレーション検証。
- 主なタスク: 本体PasteControl、拡張での取込可否の実機試験、保持上限、削除・保存取消、拒否UI、全削除、バックアップ除外。
- 成果物: 手動履歴機能、保存・プライバシー設定、権限別動作表。
- 完了条件: 権限拒否で自動読取せず、保存は明示操作のみ。履歴1件を正しく挿入し、重複・ピン・検索・削除が機内モードで動く。
- リスク: フルアクセスと貼付許可の別管理、Extension内PasteControl互換、DBロック、機微情報。拡張取込不可なら本体取込を正式経路にする。

## Phase 6: 最適化・品質向上（P0: リリースゲート）
- 目的: 実際に日常利用できる品質へ仕上げる。
- 実装対象: 遅延・メモリ改善、復旧処理、アクセシビリティ、不具合修正、配布準備。
- 依存: リリースに含めるフェーズと測定基準の確定。初回はPhase 2まででもよい。
- 主なタスク: 下限OSと現行OS、代表端末・ホスト試験、長時間入力、拡張再起動、データ移行、依存監査、App Privacy・必要API理由・OSS表示の整理。
- 成果物: 品質レポート、リリースチェックリスト、利用案内、配布用成果物（後続作業）。
- 完了条件: Phase 2で決めた性能目標を満たす。重大な誤削除・データ損失がなく、通信不要・権限取消・削除操作を確認。配布条件を再確認。
- リスク: OS変更、メモリ終了、App Review、依存更新。数値基準未達なら対象機能を絞って再検証する。
